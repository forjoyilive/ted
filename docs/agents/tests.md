# Tests

Rules for writing or changing any test, fixture or stub. They are part of `AGENTS.md` and bind the same way. Paths are from the repo root.

- Tests never register a login item or keep the machine awake. The daemon holds the machine awake only through `holdAwake`, which `main.ts` leaves out when `TED_STAY_AWAKE=off` (set in `vitest.config.ts`); `TED_LOW_PRIORITY=off` (also set there) starts TED’s work at normal priority whatever the setting says, because lowered work starves beside the test workers, and only `low-priority.test.ts` turns it back on; the app touches login items only when packaged, and `TED_LOGIN_ITEM_LOG` (with `TED_LOGIN_ITEM_STATUS`) makes it write each change to a file instead (ADR 0038). `TED_SKIP_FIRST_LAUNCH=1` (also in `vitest.config.ts`) makes an unpackaged app skip the Set up TED screen; tests of that screen launch with it empty (ADR 0059-first-launch-and-billing-choice).
- Test through public seams: `TedStore`, the daemon’s HTTP API, the daemon process, the `ted` binary, the Electron app (through Playwright’s `_electron`). A test that starts a daemon, a Run or the app costs seconds, and the suite must stay fast enough to run before a merge: before adding one, extend an existing test that has the same setup (same Workflow, daemon options and stub settings) with the new assertions; add a new one only when the setup differs, and say why in the commit. Check logic that needs no daemon (a parser, `queueOrder`, a pure helper, a store method) in a test of that function, not through a Task. Don’t repeat a scenario for every mode or variant when one line of code differs; cover the difference once. A test that fails in two full runs for no code reason is a defect: fix its timing or delete it. Wait for the state TED itself checks, never for the first sign that something happened: a passed Check run doesn't mean TED has finished with it (wait until the Task has no `checksActive` and is no longer `working`), and a request a working Run posts stays out of the Comments and the Inbox until its turn ends (ADR 0141), so read it with `waitUntil`, not once. A stub Task Lead that must receive an answer ends its turn, because answers arrive only at a tool-call boundary or turn end. Nothing a test uses may be shared with another test file running at the same time: no fixed port, path outside its temp home, browser profile or lock. Assert only on the fields a test is about, with `toMatchObject` or a projection; never list every field of machine settings, Task defaults, a Task or a Factory in `toEqual`, because other work adds fields and the merged result then fails. Compare whole machine settings only against `defaultMachineSettings`. `vitest.config.ts` points `TED_CLAUDE_BIN` and `TED_CODEX_BIN` at the stub agents and `TED_ANTIGRAVITY_BIN` at a missing file, so no test runs the machine’s own agent CLIs unless it sets one. Tests that start Runs use the stub agents `packages/daemon/test/fixtures/stub-claude.ts` and `stub-codex.ts` and call `killRunHosts` in cleanup, because hosts outlive the daemon; a host that has not started when its daemon stops refuses to start (its launch authority is revoked), so a test that restarts the daemon under a Run waits for the host’s `start` record first (`hostsStarted` in `test/helpers.ts`), and cleanup that must catch a host still starting calls `killRunHosts(home, { waitForStart: true })`; a test whose daemon was started by the app or `ted` stops it and its hosts with `stopDaemonIn(home)` from `packages/daemon/test/helpers.ts`. The stub follows the `{"steps": […]}` JSON in its prompt, or on any one line of it, so a Task Lead test puts the steps in the Task’s title. Tests that start Tasks clone a local repo made by `makeOriginRepo` in `packages/daemon/test/helpers.ts`.
- Every test must pass at any machine load: `pnpm check` runs 6 Node and 3 Electron workers beside TED’s own Runs, so a test can run several times slower than it does alone. A test waits only for a condition it can check (a state TED records, an event, a request, a file written whole), never for time to pass, and gets TED’s clocks and poll intervals through the options `startDaemon` and the test harnesses already take (`retention.now`, `mergePollMs`, `checkEveryMs` and the like) instead of real delays. A wait inside a test has no budget smaller than the trip it covers: walking a Task to a sign-off goes through `toSignoff` in `test/merge-harness.ts`, not a fresh `waitUntil`. In the app, measure an element only once it exists with a nonzero box (an image only once it has loaded and decoded, a window only once the renderer reports its new size), and read a style only once the setting that changes it has reached the renderer. A stub or fixture that writes state a test reads writes a temp file and renames it into place. A test’s timeout covers its work under that load, about three times what it takes alone: a test that walks a Task through several Stages sets its own (`90_000` and up), not the default 30 seconds. A longer timeout, a sleep or a retry is never the fix for a race: find what the test raced and wait for that. Code that compares elapsed time takes its start from the same clock read as its first check, so a pause between two reads can’t use up a short budget.
- `packages/daemon/test/support/setup.ts` gives every test file `TED_TEST_RUN`, `TED_TEST_FILE` and `TED_EXIT_WITH_PID` in `process.env`. Spawn children with `{ ...process.env, … }` so they inherit them: the daemon, Run hosts and the app exit when the `TED_EXIT_WITH_PID` process dies, and after each file and after the run, Vitest kills every process whose environment carries that file’s or run’s ID, and nothing else. Close Electron apps with `closeApp` from `packages/app/test/close-app.ts`, which kills the app if `close()` hangs; when the test has failed it first saves a screenshot, the window’s text and the test home’s `logs/` and `runs/` under `node_modules/.cache/ted-test-captures/<run>/` and prints the folder. After launching the app, wait with `loadedWindow` or `appLoaded` from `packages/app/test/first-window.ts`, which wait for `data-loaded="true"` on the app’s root (the first Factories load has ended); the sidebar draws before the data arrives. Assert on what stays (the daemon’s record, a list), not on text the app shows for a moment. `expect.poll` waits up to 10 seconds (`vitest.config.ts`). A stub step that acts on the human’s answer goes in `everyMessage`, so it runs when TED delivers the answer, not before. Build the renderer in app tests only with `buildRenderer` from `packages/app/test/build-renderer.ts`, which builds once per run: a second build empties `dist/renderer` under apps other files are starting. `DaemonClient` uses `node:http`, not `fetch`: Electron’s `fetch` throws `setTypeOfService EINVAL` outside any `await` when the daemon resets a connection. The app writes uncaught exceptions to `TED_HOME/logs/app.log` and shows no dialog when launched by tests.
