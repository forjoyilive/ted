# In-app updates hand the daemon over, and old Run hosts are replaced at an idle point

Status: accepted (KRI-123)

## Context

Spec 3.4 asks Ted to update itself without stopping Runs: one stable channel, a download in the background, a “Update ready · Restart” chip and a menu item, a restart that waits up to 10 minutes for running Checks and an in-progress merge, an install the next time every window closes or at the next launch, and the warning banner “Update to 1.4 failed” with **Download**. Spec 14 picks electron-updater for every package. ADR 0031’s supervisor restarts any daemon that stops while the app is open, so an update has to tell it first. Run hosts are detached (ADR 0013) and keep running across the restart, so a new daemon may meet a host built by an older Ted.

## Decision

- **Where it lives.** The app’s main process owns updates. `packages/app/src/updates.ts` holds the state (`UpdateStatus`: idle, unavailable, checking, up-to-date, downloading, ready, finishing, restarting, failed), the restart sequence (`createUpdates`) and every label the window and menus show, with no Electron import. `main.ts` wires it to electron-updater, the window and the supervisor, and sends `{ type: 'update', status }` on `ted:event`; the renderer asks with `updateStatus`, `checkForUpdates` and `restartToUpdate`.
- **Feed.** `electronUpdateSource` points electron-updater at the GitHub releases of `releaseRepo` with `setFeedURL`, so the feed is fixed in code, not read from `app-update.yml`. It downloads on its own, never takes prereleases or older versions, and never uses a development update config. Every request on electron-updater’s `electron-updater` session is cancelled unless it is HTTPS to `github.com` or a `*.githubusercontent.com` host (`allowedUpdateUrl`). Ted checks 10 s after start and every 4 hours, and on **Check for updates**. Only a packaged app checks; run from source, About says “Only an installed copy of Ted updates itself.”
- **What is checked before anything runs.** electron-updater compares every download’s SHA-512 with the one in the release’s `latest-*.yml` before it reports it downloaded. On macOS the install goes through Squirrel.Mac, which refuses an update whose code signature doesn’t satisfy the running app’s designated requirement (same Developer ID team), so an unsigned or differently signed bundle is never installed. Linux packages carry no signature electron-updater checks; their only protection is HTTPS to GitHub and the SHA-512 from the same release.
- **Restart.** `supervisor.handOver({ onWork })` (`packages/daemon/src/launch.ts`) polls `GET /update/work` (`{ checks, merges }`: unfinished Check runs and in-flight merge cycles) every second for up to 10 minutes, showing “Finishing 2 Checks…”, then closes the supervisor so the stop isn’t a crash, sends `POST /shutdown` with `keepRuns`, and waits for the daemon to exit. The app writes `pending-update` (the version) in its profile folder and calls `quitAndInstall`. The new app starts a new daemon, which reattaches every live Run as at any start. New Checks or merges that start during the wait are not held back; ones the 10 minutes cut short run again on start (ADR 0044, ADR 0056).
- **Without a click.** When the window closes with an update ready that needs no password, Ted writes `start-in-background` in its profile folder and restarts the same way; the next launch reads and deletes it and opens no window. electron-updater installs on quit (`autoInstallOnAppQuit`), which covers “at the next launch”. deb and rpm ask for a password through `pkexec`, so for them Ted installs only when the human clicks; the chip reads “Restart to update (asks for your password)”.
- **Failure.** An error from the installer after the restart began, or a launch whose version is older than `pending-update`, is the status `failed`, shown as the renderer-built warning banner “Update to 1.4 failed” with **Download** (the releases page). Like the keeps-stopping banner (ADR 0031) it is built in the renderer, because the app, not the daemon, knows. After an installer error the app clears `pending-update` and calls `supervisor.resume()`, which starts a daemon again.
- **Old hosts.** The host writes `v: hostProtocol` in each `start` record (`packages/daemon/src/runs/host-files.ts`). A daemon that reattaches a Run whose last `start` record has `v` below `oldestHostProtocol` replaces the host at the Run’s next idle point: it writes a `launch.json` that resumes the agent’s session, SIGTERMs the old host, drops the old host’s `exit` record instead of finishing the Run, and starts a new host on the same Run directory. The Run, its Conversation and its id stay the same. A Run’s extra environment is kept in `runs/<id>/env.json` (0600) so the new host gets it; Runs started before this change have none. Both numbers are 1 today; raise `hostProtocol` and `oldestHostProtocol` together when a change to `launch.json`, `host.log` or `input.jsonl` would break an older host.

## Considered Options

- **The daemon waits for Checks itself inside `/shutdown`.** The request would stay open for up to 10 minutes, past the client’s request timeout, and the chip couldn’t show progress.
- **Holding back new Checks and merges while an update waits.** Needs a pause in several places in the Tasks module for a few seconds of gain; a cut-short Check already reruns.
- **Testing through electron-updater with a development update config.** Unpackaged, Squirrel.Mac refuses to install (the development Electron isn’t signed) and the AppImage updater needs `APPIMAGE`. Tests instead set `TED_UPDATE_FEED` (honoured only when the app isn’t packaged, and only for a loopback `http` URL), which swaps in a small source that reads `latest.json` from a local stub server and records installs to `TED_UPDATE_LOG`.
- **Raising the failed-update banner through the daemon.** The daemon is stopped while the install runs, and the app is what knows the version it expected.

## Consequences

- `pending-update` and `start-in-background` live in Electron’s profile folder (`TED_HOME/electron` when `TED_HOME` is set).
- Things only a real signed release can show are listed on KRI-179 and KRI-180: Squirrel.Mac’s signature check and install, the AppImage replacing itself, `pkexec` with deb and rpm, `resources/package-type` in the Linux packages, electron-updater’s requests passing through the session filter, and a Run surviving a real install.
- Releases are published by `pnpm release publish` from the user’s Mac (ADR 0154-releases-are-built-tried-and-then-published-from-this-mac). `.github/workflows/release.yml`, started by hand, still only makes a draft.
- Linux updates are only as trustworthy as Ted’s GitHub releases and TLS. Signing Linux packages and checking that signature before install is open.
