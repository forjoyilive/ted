# Design

## Goal

Decide how to build the change before building it.

## Skip when

The change is small and the approach is obvious. Post a one-line note saying Design had nothing to decide, then run `ted outcome advance --skip`.

## Steps

1. Read the code the change touches and the repo’s own `AGENTS.md` or `CLAUDE.md`, if there is one.
2. Work out the approach: which files change, what new pieces there are, and how it will be tested.
3. For UI work, include a prototype or a link to the design.
4. Post the approach as a note for the human, with the choices you made and the ones you left open.

## Done when

The approach is posted. Then report the outcome.

## Ask the human when

Two approaches are both reasonable and the choice changes what the human gets. Lay out both in the note.
