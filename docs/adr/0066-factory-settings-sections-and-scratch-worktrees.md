# Factory settings edit every `.ted/` file through one Save, and Run now uses a scratch worktree

KRI-147 adds the Workflow, Checks, Agents, Permissions and limits, and Factory notes sections to the Factory settings panel (spec 5.4), and the invalid-file notice (spec 4.11). They use the save path of ADR 0061.

**Changes name only what changed.** `FactorySettingsChanges` keeps the whole `repos` list and gains optional fields: `stages` (per Stage `enabled`, `gate`, `maxBack`, `depth`), `stageFiles` (a Stage file’s new text, or `null` to delete the Factory copy), `checks` (the whole list, each entry naming its loaded position as `was`), `agents` (`lead`, `reviewer`, `planner`; `null` removes the key), `permissions`, `maxWorkingRuns` (`null` removes it) and `notes`. A missing field leaves that part of the file alone. `workflow/edit.ts` applies them to the YAML document, keeping comments and style as before.

**One commit, several files.** A save can now change `.ted/workflow.yaml`, `.ted/stages/<id>.md` and `.ted/notes.md`. The daemon builds the full Factory layer after the edit, runs `checkLayer` on all of it, and commits every known file that differs from the default branch (`null` deletes it). When the default branch’s layer is broken, the panel shows the last valid layer, so a save writes the last valid version plus the edits and replaces every broken file; the Save dialog shows a diff per file. Unknown Stage files are left alone and listed as ignored.

**Override and `based_on`.** Override copies the inherited Stage file (TED default or Library) into `.ted/stages/<id>.md` and writes `stages.<id>.based_on`. The hash is the first 7 hex characters of the git blob hash of the inherited text (`stageFileHash` in `workflow/layers.ts`), so it matches `git hash-object` and needs no repo. Reset to inherited deletes the copy and its `based_on`. KRI-149 compares this hash for drift.

**Bypass needs confirming.** A save that turns `permissions` from anything else to `bypass` is refused with 409 unless the request carries `confirmBypass: true`. The preview returns `turnsOnBypass`, and the Save dialog shows a red box with a checkbox that must be ticked before Save is enabled; the pull request body says that the save turns on Bypass. Whether a committed file may turn on Bypass at all is open in KRI-165.

**Run now uses a scratch worktree.** `check-tries.ts` keeps one detached worktree per Factory repo under `TED_HOME/scratch/<factory id>/worktrees/<repo name>`, made from TED’s clone at `origin/<base_branch>`. On creation TED copies the repo’s files to copy and runs its `setup`; a later Run now fetches and runs `git reset --hard` and `git clean -fd` to `origin/<base_branch>`, keeping ignored files such as installed packages. The Check runs like a Validate Check (login shell, the repo’s `worktree.env`, `CI=1`, its timeout), one at a time per Factory, and **Stop** ends its process group. Run now is refused while the disk hold stops new work. Cleanup removes only plain folders inside `TED_HOME/scratch` through `removeInside` and never follows a link. The last result of each Check name and its output are kept in `state.json` and `logs/` next to the `worktrees/` folder, and each change is sent as a `check-try-updated` event. A worktree unused for 24 hours is removed by an hourly sweep and before each Run now; the folder is counted under Scratch worktrees in Settings → Storage. A Check that exits 127 raises the same “A Check’s command wasn’t found” banner as Validate. The routes (`POST /factories/:id/checks/try`, `POST …/checks/try/stop`, `GET …/checks/try/output`) run a command the human typed, so the POST routes are app-only.

**Invalid file.** `Workflows.resolve` raises a warning Factory banner, `workflow-invalid`, while the Factory layer is broken (“.ted/workflow.yaml has an error on line 12 · using the last valid version (a1b2c3d)”), and clears it once the layer is valid. The panel’s notice names file, line, column and message, the last valid commit and its commit date, and links to the line on GitHub. The Task thread adds “Used last valid TED settings: <file> has an error” to each Stage entry whose recorded layers include a last-valid or skipped Factory or Library layer; it is derived from the existing Stage-entry event, so no new event is needed.

## Considered Options

- **Sending the whole edited `workflow.yaml` settings as an object.** Rejected: the daemon could not tell an inherited value from one the Factory sets, and would write every inherited value into the file.
- **A fresh worktree for every Run now.** Rejected: `setup` (installing packages) can take minutes; the spec keeps one and resets it.
- **Running Run now from the saved file only.** Rejected: the ticket’s flow is to add a Check and try it before saving.
