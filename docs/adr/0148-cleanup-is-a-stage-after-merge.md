# Cleanup is a Stage after Merge

Ted moved a Task to Done as soon as its last pull request merged, and Done stops the Task Lead, stops the Apps, runs `teardown` and removes the worktree. Work that belongs after the merge had nowhere to happen: a setup Task told the user it couldn’t post an Asana comment after the merge, and test environments or emulators a Task started outside Ted were left running (TED-307).

**Cleanup is an optional agent Stage between Merge and Done.** A Factory turns it on with `stages.cleanup.enabled: true` and lists named steps under `stages.cleanup.steps`, each `{name, instruction}`. Without a step it stays off, and missing `enabled` means off, unlike every other Stage. It is never listed in `order`: `workflow/check.ts` refuses it there and refuses keys other than `enabled`, `effort`, `based_on` and `steps`, and `built` in `workflow/resolve.ts` appends it to the resolved order only when `cleanupOn` says it is on. So existing Factories and their own `order` lists need no change.

- **Entering.** `move` turns a move from Merge to Done into a move to Cleanup when the Task’s Workflow has Cleanup. Every way a merge finishes (the merge watcher, `markDone` for the human, the Task Lead and the Coordinator) already ends in that call, so none of them changed. The same Task Lead Run gets the Cleanup Stage file with the steps appended, through `deliver` with a slot; a Task whose Lead has ended is resumed with a fresh Run from the brief. `finish` still runs only on entering Done.
- **Merged.** `taskIsMerged` counts Cleanup as merged, so blocked Tasks, parent rules, setup and repair continuation move on at the merge, and the wake-up that releases blocked Tasks fires on entering Cleanup. Tracker sync (`tasks/tracker-sync/sync.ts`) moves a Linear issue to completed only at Done; retention already counts from Done.
- **Reporting.** `ted cleanup report "<step>" done|skipped|failed "<what happened>"` calls `POST /tasks/:id/cleanup-steps` (`runToken: true`, current Task Lead only, its own Task, Cleanup only, a step the Workflow lists). The text goes through `redactSecrets` and is recorded as `v1.CleanupStepReported`, a thread line per step. `ted outcome advance` in Cleanup is refused until every listed step has a result. With none failed, the Task moves to Done.
- **Failing.** With a failed step, Ted posts a `question` with the choices Try again and Finish anyway and a `cleanupFailure` field (`v1.CommentCleanupFailureAsked`, purpose `cleanup-failure`), and the Task stays in Cleanup with `cleanupFailed` in `TaskFacts`. Try again records `v1.CleanupRetried`, which clears those steps’ results, rereads the Workflow with a fetch and sends the Task Lead only the failed steps with their current instructions. Finish anyway records `v1.CleanupFinishedAnyway`, posts a Ted note naming the steps that didn’t happen and moves the Task to Done. Autopilot answers only questions a Run asked, and the Coordinator’s `mayAnswer` refuses this one, so only the user answers it.
- **Refusals.** `ted outcome back` is refused in Cleanup: the code has merged, and more work is a Follow-up Task. Mark done, `ted task done` and the Coordinator’s done are refused while a Task is in Cleanup. Archive stays available, as for any open Task.

## Considered Options

- **A “cleaning up” flag on Done.** Rejected: much of Ted treats Done as closed (no Runs, no requests, worktree gone), and the user chose a Board column of its own.
- **Only shell hooks**, such as a second after-merge command beside `worktree.teardown`. Rejected by the user in Clarify: posting to another tool needs the Task Lead’s judgment and access. Command steps Ted runs itself come in TED-320.
- **Listing Cleanup in `order`.** Rejected: one switch is simpler, and every Factory’s own `order` would otherwise need editing.
- **A Skip action.** Rejected by the user in Clarify: the only ways out of a failed Cleanup are Try again and Finish anyway.

## Consequences

- A merged Task can sit in Cleanup with a live Task Lead and its worktree, so anything that asks whether a Task is merged must decide whether Cleanup counts; `isMerged` says yes, `stage === 'done'` says no.
- The Factory and Library settings pages leave Cleanup out of their Stage rows. Factory settings has its own Cleanup page instead (TED-321): an on/off switch and the steps, saved as `cleanup` in the settings changes and written by `writeCleanup` in `workflow/edit.ts`, which keeps the steps when Cleanup is turned off. It shows only the Factory layer’s Cleanup, as the Checks page shows only its own Checks. The Library page has no Cleanup editor; a Library Cleanup is edited in its `workflow.yaml`.
