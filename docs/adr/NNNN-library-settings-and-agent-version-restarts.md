# Library settings write straight to `TED_HOME/library/`, and idle Runs restart onto new agent versions

KRI-148 adds Settings → Library, the agent defaults under Settings → Agents, and **Restart idle Runs onto new agent versions** (spec 4.9, 7.3, 11.3).

**One module writes the Library.** `packages/daemon/src/library-settings.ts` serves `GET /library`, `POST /library/preview` and `POST /library/save`; the two POST routes are app-only. A save takes `LibraryChanges`, the Library subset of the Factory settings changes from ADR 0066: `stages`, `stageFiles` and `agents`. `workflow/edit.ts` applies them with the same `applyChanges` as Factory settings (its `repos` part now only runs when `repos` is given). The daemon builds the whole Library layer after the edit and runs `checkLayer` on it; any error refuses the save and nothing is written. Each changed file is written to a temporary file in the same folder and renamed into place, so an outside reader never sees half a file, and a link at a file’s path is replaced, not followed. Only `workflow.yaml` and `stages/<built-in id>.md` are ever written or deleted. The save is refused with 409 when the folder’s content hash (`contentVersion`) differs from the one the page loaded.

**`based_on` works as in Factory settings.** Edit in Library copies TED’s default Stage file and records `stages.<id>.based_on` in the Library’s `workflow.yaml` as `stageFileHash` of the default text; Reset to default deletes the copy and its `based_on`. KRI-149 compares this hash for the Library’s “Default version changed” row.

**Watching.** `library-watch.ts` creates `TED_HOME/library/` at daemon start and watches it recursively with `fs.watch`. After a change settles it calls `Workflows.inherited()`, which validates the layer and records it as the last valid version when it passes, then emits the new `library-changed` live update; the Library page and the Agents defaults reload on it. A broken Library keeps resolving to its last valid version (ADR 0019, spec 4.11), and the Library page shows the same amber notice as Factory settings, without Open on GitHub. Saving from the page writes the last valid version plus the edits, replacing the broken file. With the folder always present, the Library layer is recorded as `valid` with no files instead of `absent`.

**Agent defaults are Library settings.** Settings → Agents edits `lead`, `reviewer` and `planner` in the Library through the same save, one change at a time, with no save bar. A row shows Library when the Library sets the key, otherwise Default with TED’s resolved choice; **Reset to TED default** removes the key.

**Restart onto new agent versions.** A machine setting, `restartIdleRuns`, on by default. Agent health reports every version it reads through `onVersion`; `runs/version-restarts.ts` compares it with the last version recorded in `TED_HOME/agent-versions.json`. When a kind’s version changes and the setting is on, every live Run of that kind is marked; each restarts through `Conversations.restart` (ADR 0027: same Run, resumed session, same flags) as soon as it is idle, so a working Run restarts when its turn ends. Waiting Runs are left alone until they go idle. Marks live in memory, so a daemon restart before a marked Run goes idle forgets it; the next version change marks it again.

## Considered Options

- **A Save dialog with a diff for the Library, like Factory settings.** Rejected: there is no pull request to describe, and the spec has Save write at once. Compare with default shows the diff that matters while editing.
- **Storing the last seen agent versions in the store.** Rejected for now: a new event and table for one value per agent kind, which nothing else reads.
- **Recording each Run’s agent version.** Would let TED restart only Runs on an older version, including after a daemon restart, but needs a new `RunStarted` version; left until something else needs it.
