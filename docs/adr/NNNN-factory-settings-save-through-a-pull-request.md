# Factory settings edit `.ted/workflow.yaml` in the daemon and save it through one pull request

The Factory settings panel (spec 5.4) changes two kinds of setting. Settings saved on this machine (the Factory’s name and each repo’s local folder) are store events that apply at once: `v1.FactoryRenamed`, `v1.LocalFolderSet` and `v1.LocalFolderCleared`. Settings saved to the repo are collected in the app until the human saves them, and the daemon turns them into one commit on the primary repo’s default branch.

**One module.** `packages/daemon/src/factory-settings.ts` owns the panel’s routes (`GET /factories/:id/settings`, `POST …/settings/preview`, `POST …/settings/save`, all app-only). It reads `.ted/` from `origin/<default branch>` like the Workflow does (ADR 0019); when that file is broken it loads the layer’s last valid version, and saving replaces the broken file. The app sends the whole edited `repos` list, each entry naming the repo name it had when loaded (`was`). `packages/daemon/src/workflow/edit.ts` applies that list to the YAML document with the `yaml` library, so comments, key order and every key the panel doesn’t show stay as they were; a renamed repo also renames each Check’s `repo:`, and a dropped repo drops its Checks. Flow collections keep the file’s own padding.

**Never invalid.** Before any commit the daemon checks the edit (names, environment variable names, Apps) and runs `checkLayer` on the new file; any error refuses the save with the message, and nothing is pushed. The preview route returns the same problems, the diff and the side effects, so the dialog shows why. A save also carries the version of the file the page loaded; if the file changed on GitHub since, the save is refused.

**Commit and push.** `commitAndPush` in `git.ts` builds the commit in a temporary bare repo whose `objects/info/alternates` points at TED’s clone, with its own index file: `read-tree`, `hash-object --no-filters`, `commit-tree`, then push with hooks and `ext::` off to the Factory’s stored clone URL. Nothing runs in the clone or a worktree, so config an agent can write there never applies (ADR 0048). The branch is `ted/settings-<time>-<random>`; the pull request is “Update TED settings” to the default branch, opened through the `Gh` runner.

**Save and merge** reads the pull request with `readPullRequests` and `nextStep` from `tasks/merge.ts`, with no Task, no Validate and no CI wait, and merges with `gh pr merge --match-head-commit` using the primary repo’s current `merge_method`. A required review or a blocked merge leaves the pull request open and returns the reason; while GitHub hasn’t decided mergeability TED asks again for up to ten seconds. Save is refused while `gh` isn’t ready.

**Repos follow the file, but TED clones only repos the human added.** The Factory’s repos in the store (names, order, clone URLs) follow the default branch’s `repos`: every `Workflows.resolve` calls `storedRepos`, and `Factories.syncRepos` records `v1.FactoryReposChanged`. Renames, reorders and removals apply at once; a repo dropped from the file stays in the store while an open Task uses it. A repo new to the Factory is added and cloned only when the human added it from this machine: a Save approves the repos it adds after they pass the same access check as Add Factory. A repo that appears in the file any other way (merged on GitHub, written by a setup Task) raises a `repo-in-workflow` Factory banner, “.ted/workflow.yaml adds owner/repo”, and **Add** runs the access check and then adds and clones it. Repo names must be two safe path segments (no `.` or `..`), a clone path must stay inside `TED_HOME/repos/`, and a Factory has at most 10 repos (`checkLayer` refuses more). A clone that fails raises the clone-failed banner, whose Retry clones every missing repo of the Factory.

## Considered Options

- **Committing in TED’s clone with `git commit`.** Rejected: it runs hooks and filters from config an agent can write through a worktree, and it moves the clone’s checkout.
- **Sending a YAML text from the app.** Rejected: the app stays a thin client (ADR 0011), and only the daemon can check the result against the Workflow rules.
- **Updating the store from the panel only.** Rejected: a “Save as pull request” merged later on GitHub, or a setup Task, changes `repos` too, so the store follows the file wherever it changed.
