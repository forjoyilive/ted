# Task browsers use an authenticated app bridge

A Task’s browser is an isolated Electron WebContentsView owned by the app, showing the same page to the human and the Task’s agents. The daemon authorizes each command against the Task and its running web App, and relays it over an app-authenticated poll and reply channel. A debugging port would expose browser control outside Ted’s Run-token boundary; putting Electron in the daemon would couple background work to a desktop window.

Each Task has one page and an in-memory session, retained while switching views and reset when Ted quits. The browser replaces the middle pane while open. Preview opens local web Apps there; hosted previews and the explicit Open ↗ action use the default browser. Agent commands do not select a different Task or bring the window forward.

The guest has no preload, Node integration, Ted credentials or IPC access. Its network requests, frames and redirects stay on the selected App’s exact origin, including equivalent WebSocket URLs, with one exception: images, fonts, audio and video (`isOutsideMedia` in `packages/app/src/browser-proxy.ts`) may also load from public internet hosts, because Apps commonly show art from a CDN and an empty page is worse than the small leak. Such a request’s address can still carry data out of the page; scripts, stylesheets, frames, fetches, form posts and sockets to other hosts stay blocked, and no file type reaches loopback, private or link-local addresses. The page counts the requests it blocked, and the Task browser shows “Blocked N requests to other sites · Open ↗”, reset at each new document. Popups, file choosers, downloads, permissions and system client-certificate selection are blocked. This deliberately leaves external authentication and other CDN dependencies to the default browser. Snapshot references belong to one page revision; navigation and agent mutations invalidate them. Commands expire and are never replayed after a bridge restart, because repeating a click can repeat a side effect.

Browser commands and page contents remain transient. Screenshots use the existing attachment store and ownership rules; capturing alone does not post a Comment. A v1.TaskBrowserCaptureAdded event records each saved file’s Task ownership before the broker answers, independently of Comments or request attachments. This survives daemon restart and includes unposted captures in Task/Factory deletion; files shared with other Tasks remain protected by filesInUse(). Task teardown and App stop/restart cancel pending commands; deleting a Factory removes its Tasks and their browser state through the same path.

The bridge follows the supervised daemon client after reconnect. Idle pages and sessions survive transport failures. Reconnect reconciles every retained App against the current client and connection generation, since lifecycle events missed during a disconnect are not replayed; obsolete checks cannot clear a newer session. Temporary validation failures retry while that connection still owns the session. An interrupted command closes its guest while retaining the session, so queued input cannot run later. Each command has a deadline, checked inside injected scripts and before input dispatch, and a stalled guest never blocks polling for another Task. Native input revalidates the page revision after awaited lookups and before each dispatch. Main-frame navigation invalidates references when it starts; if a partial input crosses navigation, the guest is closed before its release can reach the new document. CLI recovery acquires the client before issuing a browser mutation and never retries that mutation.

Guests bootstrap in a blank document before the internal debugger installs a script in each new frame that makes WebRTC peer connections unavailable. WebRTC bypasses the HTTP request filter; removing only UDP would leave other ICE transports open. Every request other than the selected App’s scheme, host and port goes through a forward proxy in the app’s main process (`startGuestProxy`), which also constrains transports that skip webRequest, including worker WebTransport. Chromium refuses WebTransport through that proxy; implicit loopback bypass is explicitly removed. The proxy listens on loopback and gives each page its own random login (`admit`), released when the page is replaced or closed. The app gives that login only to Chromium’s proxy `login` event for that page and to the page’s sign-in request, so no other process can use the proxy. Chromium never asks for proxy credentials for a page’s images, fonts or media; it only reuses credentials its session already holds. Because the App’s own origin skips the proxy, a page would otherwise get 407 for every outside image, and its requests would never reach the address check or the blocked count. So before App scripts load, the main process signs the page in: an Electron `net` request in the page’s session to `http://ted-guest-proxy.invalid/` with the page’s login, which the proxy answers with 204 and never forwards. The page installs its own request filter before signing in, and that filter lets through only this main-process sign-in request, so a filter left by the session’s previous App can’t cancel it. Each refusal the proxy makes counts toward the blocked line of the page whose login sent the request. It accepts only `GET`/`HEAD` and `CONNECT`, resolves each host itself, refuses the host unless every address is public, and connects to the address it checked, so a name that later resolves to a local address (DNS rebinding) can’t reach Ted’s daemon or another local service. The webRequest filter decides the file type; the proxy decides the destination. A guest opened without a proxy keeps the old rejecting one. The guard is registered before any App scripts load, including on reload and in child frames. Retained sessions keep the identities and generations of every visited App even when their guest is canceled or another App is selected. A stop or restart of any visited App clears the shared Task session and its connections; ordinary App switching retains it. Pending lifecycle checks follow that session until it is replaced, so changing the selection cannot discard a teardown result. If clearing the shared session closes another still-running selected App, Preview reopens that App through the same harmless open/retry path used for recovery.

Before replacing a guest in a retained session, Ted unregisters and stops its service workers and closes its existing connections before changing the selected-origin policy. Unregistering alone leaves a worker’s pending events and WebSockets alive, so a temporary sandboxed blank guest uses the internal ServiceWorker domain to stop execution in that session. It never displays content, exposes a debugging port or receives repo scripts, and closes after cleanup. Cookies, local storage and other page storage survive ordinary App switching; service-worker registrations do not. Full lifecycle teardown performs the same worker cleanup even when the original guest has already closed, then clears all session storage.
