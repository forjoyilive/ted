# The Coordinator drafts Agents the user creates

Status: accepted (TED-433). Builds on ADR 0179-agents-are-defined-in-agent-files, ADR 0180-a-chat-records-its-agent-and-ted-checks-its-powers, ADR 0067-library-settings-and-agent-version-restarts and ADR 0061-factory-settings-save-through-a-pull-request.

The user can ask a Coordinator chat for an Agent (“make me an Agent that answers questions about our billing code”) and get a draft to approve, instead of editing `agents.yaml` by hand. Agent files decide what later chats may do, so no Run may write them: the chat only drafts, and only the user’s click saves.

**A new power, Manage Agents (`manage_agents`).** The built-in Coordinator has it; a layer can give it to any Agent but the Planner, which runs in planning chats (`ted workflow check` reports it on `planner` as an error and `resolveAgents` drops it, as with `manage_tasks`). `requirePower` checks it on the chat’s stored Agent for both Run-token routes below.

**The chat reads Agents and posts drafts.** `GET /coordinator/agents` (`ted coordinator agents`) returns the Factory’s resolved Agents with their instructions, fenced as data. A draft is a chat request of kind `agent` through `POST /coordinator/requests` (`ted coordinator agent-draft --file`), so it reuses one-open-request-per-chat, `--supersedes`, the Inbox, snooze and withdrawal on archive. `parseAgentDraftInput` refuses a bad id, a power outside `agentPowers`, a name over `maxAgentName` and instructions over `maxAgentDraftInstructions` (20,000 characters). `planDraft` in `chats/agent-drafts.ts` refuses a new draft whose id exists, a change (`"change": true`) to an id that doesn’t resolve, chat-only powers on the Planner and a change that changes nothing; it passes the name and instructions through `redactSecrets` and stores, for a change, the Agent as it was (`current`, with a hash) so the card can show what differs. The draft is `v1.ChatAgentDraftPosted`, committed with its `v1.ChatRequestPosted` into the request row’s `agentDraft` column.

**Only the app’s Create saves.** `POST /coordinator-chats/:id/requests/:rid/agent` (`Coordinators.answerAgentDraft`) never sets `runToken` or `fileToken`, so neither a Run nor the `daemon.json` token can call it; the generic answer route refuses an `agent` request. Autopilot and the Coordinator’s `answer` action never see chat requests. The user may edit the name and instructions and untick powers; a power the draft didn’t give is refused (`chosenDraft`), so the card can narrow a draft but never widen it. Before saving, `draftStillFits` refuses when the Agent changed (or a new id appeared) since the draft, checked for This Factory against the default branch fetched just then. A change to an Agent This Factory defines can only go to This Factory: the card’s diff describes the Factory copy, so a Library save would overwrite a Library definition the user never saw. Archive, delete and Factory removal wait for a save in progress (`settle`). `saveDraft` builds one `AgentFileChange`, keeping the layer’s own Provider and model settings, and saves it through the same code the Agents settings pages use: `LibrarySettings.save` for **Library**, and `FactorySettings.save` in pull-request mode for **This Factory**. Each runs `checkLayer` first; a refusal shows on the card and leaves it open. Create records `approved` with the result text, Dismiss records `denied`, and the chat’s Run is told the outcome as a `from: 'ted'` message.

**Commands are not part of a draft.** Agents have no commands yet. TED-430 adds named commands and can add them to the card; outside commands stay a settings-page choice.

## Considered

- **Let the Coordinator write the Library itself.** Rejected: an Agent that can write Agent files can give any later chat any power, which is the decision this change exists to keep with the user.
- **Let the card add powers.** Rejected for now: the card only narrows what the user can read in the draft; adding a power is a settings-page change after Create.
- **Save and merge for This Factory.** Rejected: a repo Agent’s powers are reviewed in a pull request like the rest of `.ted/` (ADR 0179).
