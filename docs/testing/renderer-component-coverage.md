# Renderer component coverage

Baseline: [`7599ff4e61e7`](https://github.com/forjoyilive/ted/tree/7599ff4e61e75c6c0ab7f393fd2d575ee63d4f04). This inventory covers all 32 files classified as Electron tests at that commit.

## Scope and counts

The baseline contains 184 test declarations: 180 Electron cases and four pure cases living in an Electron-classified file. Two two-row parameterizations make 182 runnable Electron cases before platform skips. The migration removes 98 declarations: 92 move to component coverage (with named daemon/integration coverage where needed), two consolidate into retained Electron flows, and four pure cases move unchanged to `details.test.ts`. Every removed declaration appears below.

The result is 125 component declarations (126 runnable cases) in 19 files, four moved pure cases, and 86 retained baseline Electron declarations (88 parameterized cases before platform skips). Rebasing onto main at c40cbac preserves its 13 new Electron declarations (16 runnable cases): the Linear late-key races and image attachments, New Task drafts/submission, profile and idle chat timestamps, Coordinator interactions, and Task-content isolation. The complete current native set is therefore 99 declarations / 104 runnable cases; those upstream additions were not removed to meet a number. Electron launches drop by at least the 94 removed launch cases; the components create no Electron process or daemon.

The roughly 30-case target is exceeded deliberately. The inventory spans 32 feature/boundary files, with multiple distinct native contracts in several files: background/quit/handover, crash recovery, OS notifications/updates, shell/editor opening, geometry/scroll/drag, security/CSP and persistence. Reducing the retained set to 30 would remove those assertions or a feature’s main-path end-to-end coverage. The retained table records the reason for each case. Counts are an inventory, not a quota; this change does not claim that jsdom verifies layout, native focus, OS behavior, transport or persistence.

## Running component cases

From the repo root, run only the affected files, for example:

```sh
pnpm vitest run packages/app/test/dialogs-component.test.tsx packages/app/test/requests-component.test.tsx
```

From `packages/app`, use `pnpm vitest run test/dialogs-component.test.tsx`. Each component file selects jsdom with a file directive. TSX discovery and JSX transforms work from both roots. Component files stay in the node project’s six-worker budget; Electron remains capped at three. The existing full-suite lock, test cleanup, check-runner processes and per-file timing support are unchanged. Agents continue to run affected files only.

`test/support/component.ts` installs `window.ted`, fails unknown requests, emits explicit bridge events, and verifies that components unsubscribe after React cleanup. Pending/error tests control promises rather than starting a daemon. Fixtures use protocol types. The DOM shims implement dialog open/close, scrolling calls and xterm’s canvas capability probe only; they supply no layout or native behavior. App-level cases exercise the existing keymap listener. The only renderer production correction restores Description focus after Create more finishes and its form becomes enabled; the human approved including this upstream regression fix. Theme tokens, preload and daemon request boundaries are unchanged.
