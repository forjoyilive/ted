# Coordinators have bounded Factory authority

A Factory has one ongoing Coordinator conversation. It helps the human compare Tasks and choose next work without taking over any Task Lead’s responsibilities. It acts only when messaged, and only explicit requests in that conversation authorize starting Backlog Tasks or reordering waiting Tasks. Advice and ambiguous references require a chat reply.

`coordinators/coordinators.ts` owns its lifecycle and registers a QueueSource with Tasks. Each idle-to-working turn takes a slot at the Planning tier, under machine and Factory caps, agent health and disk holds. The Coordinator uses its own managed folder, never a repo checkout. Existing Run Conversation storage retains messages and agent output; additive Coordinator events persist identity, Run associations, phase, referenced Tasks and action receipts. Concurrent first messages share the Factory’s unique row.

The stored Run association supplies authority, rather than a request’s Factory ID or an environment variable. The server restricts these Runs to Coordinator tools, caller discovery and their own boundary operation. Ordinary Run routes cannot bypass that restriction. App-only routes create conversations, send human messages, Stop and Retry. Conversations and steering route idle messages back through the Coordinator queue; a working response receives messages only at a boundary. Failed session resumption can replace the Run while preserving earlier history and receipts. Old Runs have no action authority.

Reads return fresh facts with bounded pages and nonce-delimited untrusted Task context. Actions require current target and neighbour versions. Starts delegate to `Tasks.start`; moves delegate to `Tasks.move`, using neighbour IDs rather than client ranks. The daemon validates Factory and waiting-group membership. Per-action operation IDs and fingerprints are persisted before dispatch; an interrupted dispatch returns an uncertain receipt rather than replaying the action. Receipts preserve the actual result and before/after state, including Priority changes. Multi-Task actions are independent, never atomic.

Factory removal waits for launches and actions, stops Coordinator hosts and removes saved rows, pending messages, Conversation history and checked managed folders before FactoryRemoved. This is an explicit, narrow Factory-scoped exception to ordinary Task Run authority. It grants no power over Gates, arbitrary Stages, Task edits, credentials or settings.
