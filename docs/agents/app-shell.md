# App shell

Rules for the Electron main process, the daemon supervisor, updates, quit, notifications, packaging and icons. They are part of `AGENTS.md` and bind the same way. Paths are from the repo root.

- In the Electron main process, start work from `app.whenReady().then(...)`. Electron emits `ready` only after the ESM entry finishes evaluating, so a top-level `await` on it hangs.
- The app’s main process reaches the daemon only through `superviseDaemon` in `packages/daemon/src/launch.ts`, which restarts a crashed daemon and reports `connected`, `reconnecting` or `stopped` to the renderer. Renderer data hooks use the primitives in `packages/app/src/renderer/data.ts`: `useLive` for lists, `useReloading` for invalidated reads and `useEventValue` for event-kept values; they own subscription cleanup and reload when the connection comes back. Pages never call `ted.onEvent` directly. The daemon logs through `console`, which goes to `TED_HOME/logs/daemon.log` (7 rolling files of 20 MB); `TED_RESTART_DELAYS_MS` shortens restart delays in tests.
- Updates belong to the app’s main process: `packages/app/src/updates.ts` holds the status, the restart sequence and every label; electron-updater’s feed is fixed to `releaseRepo` and its requests may only go over HTTPS to GitHub. Anything that stops the daemon on purpose while the app runs goes through the supervisor (`handOver`, then `resume` if it must come back), or the supervisor counts a crash. Tests never reach a real update server: they set `TED_UPDATE_FEED` to a loopback stub serving `latest.json` and read installs from `TED_UPDATE_LOG`. Raise `hostProtocol` and `oldestHostProtocol` in `runs/host-files.ts` together when a host file format change would break an older host; the daemon then replaces old hosts at their next idle point.
- Closing the window hides it and Quit ends the daemon through `POST /shutdown`. Quit that stops work first writes `TED_HOME/quit-mark` (`markQuit` in `launch.ts`); while it exists no `withDaemon` call starts the daemon (`TedQuitError`), the daemon exits with `tedQuitExitCode` once it holds its lock, and a Run host won’t start its agent; the app’s launch removes it (`clearQuit`), and demo cleanup may clear it temporarily to start the daemon that stops the demo’s Apps and Runs. In a Ted Dev demo, Quit writes the mark and hands the daemon over with `keepRuns`, preserving the stub Runs for reopening; `pnpm ted dev stop` stops the demo’s daemon, Run hosts, stub agents and Apps after the app is closed, keeps its data and marks a populated demo incomplete so it needs `pnpm ted dev seed --reset`. `packages/app/scripts/demo-screenshots.ts` closes its app and calls `stopDemoFromCli` even when seeding, launch or capture fails; it reports `DemoAppRunningError` with a message to quit the open demo app first and propagates other cleanup errors. Before capture it resets an incomplete demo, replacing the home’s data and earlier screenshots in its `screenshots` folder (see `docs/development/demo.md`). If `/shutdown` hasn’t answered within the app’s wait, `stopTedProcesses` sends SIGTERM, then SIGKILL after a grace period, to every process holding the daemon lock or a Run’s `host.lock`, so a stuck daemon never leaves Runs going; the menus, quit decision and dialog text are plain functions in `packages/app/src/background.ts`, tested without Electron, and `main.ts` only wires them up. Anything that should keep Ted running or count as waiting goes into `TedStore.activity()`. A daemon started with `--exit-when-idle` exits a minute after the last hold on its idle timer (`packages/daemon/src/idle.ts`) is released, and a live Run holds it whatever its state. Periodic work must not take and release a hold on a timer shorter than the idle exit, or the daemon never exits: hold for as long as there is something to wait for (Automations, snoozes), or not at all (the Linear sync passes `holdIdle: false` to `inBackground`). Launch the app with `TED_HIDDEN_WINDOW=1` in tests and scripts: no window, tray icon, notification or quit dialog.
- The sidebar Inbox count, the Dock badge, the menu-bar count and the Linux window title all come from `TedStore.waiting()` (`GET /inbox/waiting`, the `inbox-changed` event), never from `Activity`. The store works it out again after every commit except a `recordRunOutput` commit that asks or withdraws no request (`waitingUnchanged`); an event added to that commit that can change what is waiting must not be skipped. A Factory’s notification choices are the `factoryNotifications` machine setting, read only through `factoryNotifications(settings, factoryId)` in `packages/protocol/src/settings.ts` and changed only through the app-only `PUT /factories/:id/notifications`, which merges one change into the stored map; `waiting()` marks the requests of a Factory with Inbox items off as `uncounted`, and anything that shows how many requests wait uses `countWaiting` (`packages/protocol/src/waiting.ts`), never the list’s length. Notifications are decided only in `packages/app/src/notifications.ts`; tests set `TED_NOTIFY_LOG` (and `TED_NOTIFY_STATUS=off`) so the app writes notifications and badge changes to a file and never shows one or touches the Dock.
- Start the daemon, a Run host or the Run’s `ted` shim only through `nodeEntry` in `packages/daemon/src/node-entry.ts`, which goes through `$APPIMAGE` inside an AppImage. `pnpm package [--mac|--linux] [--x64] [--arm64] [--dir]` stages the code as JavaScript in `packages/app/dist/stage/` and builds installers into `packages/app/dist/release/`; it signs and notarizes only when the Apple variables are set and never publishes. The app ships only the staged `node_modules`, never electron-builder’s own collection; `pnpm --filter @ted/app smoke` runs the built `ted task list`. The release repository and the Download URL come from `packages/protocol/src/release.ts`.
- The logo is stroke geometry in `packages/app/src/logo.ts`; the menu-bar icon, Ted Dev’s Dock icon and the installer icons are all drawn from it. After changing it or `app-icon.ts`, run `pnpm --filter @ted/app icons` to rewrite `packages/app/build/icon.icns`, `build/icons/` and `build/logo.svg` (macOS only, it needs `iconutil`); `app-icon.test.ts` fails while they are stale.
- On Linux, a process spawned from Electron’s main process inherits Chromium’s open descriptors. Start the daemon only through `withDaemon`, which closes them; any other long-lived process spawned from the app needs the same treatment.
- Crash and error reports go only through `crashReporter` in `packages/daemon/src/crash-report.ts`, which checks the `reporting` machine setting before every send, removes paths, runs `redactSecrets` and limits how many it sends. The renderer passes its errors to the main process through `reportCrash` and never posts to Sentry itself. Don’t add a Sentry SDK, breadcrumbs, log lines or minidumps to a report. Tests point `TED_SENTRY_DSN` at a loopback stub and force errors with `TED_FORCE_ERROR`.
- A value put into source code that Ted builds and runs, such as a script the browser page runs in a page (`packages/app/src/browser-page.ts`) or a file a test writes and runs, goes in through `scriptLiteral` from `@ted/protocol`, never a bare `JSON.stringify` or a template string.
- A Task browser guest loads from other hosts only what `isOutsideMedia` in `packages/app/src/browser-proxy.ts` allows (images, fonts, audio and video), and only through the guest proxy from `guestProxyRules`, which refuses every non-public address after resolving it. Each page gets its own proxy login and signs in from the main process before App scripts load, with an Electron `net` request to `guestSignInUrl` (`http://ted-guest-proxy.invalid/`), because Chromium never asks for proxy credentials for images, fonts or media and would leave them at 407, uncounted. The page’s request filter lets that one request through; keep the filter installed before the sign-in. Don’t add a file type or a direct connection.
