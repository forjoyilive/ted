# Failure cases preserve results and bind human decisions

A failed Check and a human’s acceptance answer different questions. Keep a Failure case separate from Check execution and original Findings, with durable assessment, request, resolution and invalidation history owned by Tasks. Acceptance binds one identified failure to a daemon-captured tested context; observing a changed or unverifiable context permanently invalidates that acceptance, even if the old content returns.

Use normal question Comments and atomic CommentAnswered commits for decisions so Inbox, restart and fresh Task Lead Runs share one source of truth. Serialize these operations with forward movement and remote merge actions. Explicit cases hold advancement now; existing failure producers retain their behavior until they adopt this API. Acceptance never bypasses existing Check, reviewer or GitHub merge prerequisites. The contract and its conservative context boundary are in [failure-cases.md](../spec/failure-cases.md).

Execution identity is part of acceptance eligibility. Version 2 captures include only hashes of observed failed CI repo/PR/head/attempt tuples; a source must match its capture. Finding captures must fall inside the originating Run’s recorded lifetime. Historical evidence remains recordable without a context and cannot receive acceptance by borrowing a later capture. These bindings are also verified on resolution and obligations reads. Explicitly empty GitHub status rollups are verifiable empty CI sets; missing or truncated reads remain unknown. Decision requests present appended evidence and context references, and invalid input cannot withdraw a pending decision.

Completed Tasks retain historical decisions without recapturing cleaned-up worktrees or unpolled merged PRs. Active holds preserve factual Partly merged state after external merges. Invalidation and its TED notice share one commit; existing Comment delivery tracking carries undelivered notices into health-held saved sessions as well as fresh Runs.

Assessments bind the evidence append position, not wall-clock ordering. Pending legacy assessments with additions need a fresh bound assessment; existing recorded decisions are retained. Context collection waits for GitHub and Workflow inputs before its final local tree reads so a pending remote read cannot authorize an earlier local snapshot.
