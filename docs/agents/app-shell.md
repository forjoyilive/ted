# App shell

Rules for the Electron main process, the daemon supervisor, updates, quit, notifications, packaging and icons. They are part of `AGENTS.md` and bind the same way. Paths are from the repo root.

- In the Electron main process, start work from `app.whenReady().then(...)`. Electron emits `ready` only after the ESM entry finishes evaluating, so a top-level `await` on it hangs.
- The app’s main process reaches the daemon only through `superviseDaemon` in `packages/daemon/src/launch.ts`, which restarts a crashed daemon and reports `connected`, `reconnecting` or `stopped` to the renderer. Renderer data hooks use the primitives in `packages/app/src/renderer/data.ts`: `useLive` for lists, `useReloading` for invalidated reads and `useEventValue` for event-kept values; they own subscription cleanup and reload when the connection comes back. Pages never call `ted.onEvent` directly. The daemon logs through `console`, which goes to `TED_HOME/logs/daemon.log` (7 rolling files of 20 MB); `TED_RESTART_DELAYS_MS` shortens restart delays in tests (ADR 0031).
- Updates belong to the app’s main process: `packages/app/src/updates.ts` holds the status, the restart sequence and every label; electron-updater’s feed is fixed to `releaseRepo` and its requests may only go over HTTPS to GitHub. Anything that stops the daemon on purpose while the app runs goes through the supervisor (`handOver`, then `resume` if it must come back), or the supervisor counts a crash. Tests never reach a real update server: they set `TED_UPDATE_FEED` to a loopback stub serving `latest.json` and read installs from `TED_UPDATE_LOG`. Raise `hostProtocol` and `oldestHostProtocol` in `runs/host-files.ts` together when a host file format change would break an older host; the daemon then replaces old hosts at their next idle point (ADR 0078-in-app-updates-hand-the-daemon-over).
- Closing the window hides it and Quit ends the daemon through `POST /shutdown`. Quit that stops work first writes `TED_HOME/quit-mark` (`markQuit` in `launch.ts`); while it exists no `withDaemon` call starts the daemon (`TedQuitError`), the daemon exits with `tedQuitExitCode` once it holds its lock, and a Run host won’t start its agent; only the app’s launch removes it (`clearQuit`). If `/shutdown` hasn’t answered within the app’s wait, `stopTedProcesses` sends SIGTERM, then SIGKILL after a grace period, to every process holding the daemon lock or a Run’s `host.lock`, so a stuck daemon never leaves Runs going (ADR 0134-quit-stops-work-even-when-the-daemon-doesnt-answer); the menus, quit decision and dialog text are plain functions in `packages/app/src/background.ts`, tested without Electron, and `main.ts` only wires them up. Anything that should keep TED running or count as waiting goes into `TedStore.activity()` (ADR 0028). A daemon started with `--exit-when-idle` exits a minute after the last hold on its idle timer (`packages/daemon/src/idle.ts`) is released, and a live Run holds it whatever its state. Periodic work must not take and release a hold on a timer shorter than the idle exit, or the daemon never exits: hold for as long as there is something to wait for (Automations, snoozes), or not at all (the Linear sync passes `holdIdle: false` to `inBackground`). Launch the app with `TED_HIDDEN_WINDOW=1` in tests and scripts: no window, tray icon, notification or quit dialog.
- The sidebar Inbox count, the Dock badge, the menu-bar count and the Linux window title all come from `TedStore.waiting()` (`GET /inbox/waiting`, the `inbox-changed` event), never from `Activity`. The store works it out again after every commit except a `recordRunOutput` commit that asks or withdraws no request (`waitingUnchanged`); an event added to that commit that can change what is waiting must not be skipped. A Factory’s notification choices are the `factoryNotifications` machine setting, read only through `factoryNotifications(settings, factoryId)` in `packages/protocol/src/settings.ts` and changed only through the app-only `PUT /factories/:id/notifications`, which merges one change into the stored map; `waiting()` marks the requests of a Factory with Inbox items off as `uncounted`, and anything that shows how many requests wait uses `countWaiting` (`packages/protocol/src/waiting.ts`), never the list’s length (ADR 0133-each-factory-chooses-its-notifications). Notifications are decided only in `packages/app/src/notifications.ts`; tests set `TED_NOTIFY_LOG` (and `TED_NOTIFY_STATUS=off`) so the app writes notifications and badge changes to a file and never shows one or touches the Dock (ADR 0088-notifications-and-the-waiting-count).
- Start the daemon, a Run host or the Run’s `ted` shim only through `nodeEntry` in `packages/daemon/src/node-entry.ts`, which goes through `$APPIMAGE` inside an AppImage. `pnpm package [--mac|--linux] [--x64] [--arm64] [--dir]` stages the code as JavaScript in `packages/app/dist/stage/` and builds installers into `packages/app/dist/release/`; it signs and notarizes only when the Apple variables are set and never publishes. The app ships only the staged `node_modules`, never electron-builder’s own collection; `pnpm --filter @ted/app smoke` runs the built `ted task list`. The release repository and the Download URL come from `packages/protocol/src/release.ts` (ADR 0036).
- The logo is stroke geometry in `packages/app/src/logo.ts`; the menu-bar icon, TED Dev’s Dock icon and the installer icons are all drawn from it. After changing it or `app-icon.ts`, run `pnpm --filter @ted/app icons` to rewrite `packages/app/build/icon.icns`, `build/icons/` and `build/logo.svg` (macOS only, it needs `iconutil`); `app-icon.test.ts` fails while they are stale.
- On Linux, a process spawned from Electron’s main process inherits Chromium’s open descriptors. Start the daemon only through `withDaemon`, which closes them (ADR 0011); any other long-lived process spawned from the app needs the same treatment.
