# Proposal pieces wait in Backlog, and automatic starts say why

The user saw Backlog Tasks start and couldn’t tell why (TED-505). In that Factory **Start Backlog Tasks automatically** was on, but nothing on the Task said so: its thread showed only “Task started”, the same line as the user’s own Start.

**Pieces no longer start when their blockers merge.** `createProposalTasks` in `tasks/proposal-tasks.ts` used to give every blocked piece from Split it, a planning chat or a Coordinator proposal a start request (`startRequested`), so the piece started by itself once its blockers merged. Now every piece is created without one. A blocked piece waits in Backlog until the user starts it, or until the Factory’s **Start Backlog Tasks automatically** picks it up through `backlogEligible` once its blockers have merged. **Start the unblocked ones** still starts the unblocked pieces at once. This replaces the Split it and planning chat part of ADR 0129’s “Unchanged” paragraph; a blocked Task made with Start now, and a Queued Task that got a blocker, still start once when their blockers merge. The parent Task a plan or a Coordinator proposal creates keeps its start request, because `wakeTask` uses it to finish the parent when its children merge.

A piece created before this change keeps its flag and starts once more when its blockers merge; that start clears it (ADR 0129).

**Every automatic start records its cause.** `store.queueTask` and `store.startAfterPlanning` commit `v1.TaskStartCause` (`taskId`, `cause`, `blockers`, `at`) in the same commit as the start when the Tasks module passes a cause: `factory-setting` or `snooze` from the automatic Backlog start, `blockers-merged` with the blockers’ IDs from `wakeTask`, `coordinator` from a Coordinator’s start, `automation` from an Automation’s. The user’s own Start records none. The thread shows one line for the start: the cause (“Started because Start Backlog Tasks automatically is on”, “Started because TED-480 merged”, “Started by the Coordinator”) in place of “Task started”. A start after an ended snooze also drops the “Snooze cleared” line it commits, and an Automation start that names its Automation keeps that one line. The event is a Task log row, so `v1.TaskReset` and `v1.TaskDeleted` clear it with the rest of the thread.

**A blocked Backlog Task says whether it will start.** The activity line said “Starts when TED-480 merges” for every blocked Task, which is wrong for one that waits in Backlog. `taskActivity` in `tasks/status.ts` now says “Blocked by TED-480” for a Backlog Task without a start request, and keeps “Starts when TED-480 merges” for one that has it (the `startsAfterBlockers` fact) and for a started Task. It doesn’t read the Factory setting, so the line stays true when the setting changes.
