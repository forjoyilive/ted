# Coordinators have bounded Factory authority

A Factory has one ongoing Coordinator conversation. It helps the human compare Tasks and choose next work without taking over any Task Lead’s responsibilities. It acts only when messaged, and only explicit requests in that conversation authorize starting Backlog Tasks or reordering waiting Tasks. Advice and ambiguous references require a chat reply.

`coordinators/coordinators.ts` owns its lifecycle and registers a QueueSource with Tasks. Each idle-to-working turn takes a slot at the Planning tier, under machine and Factory caps, agent health and disk holds. The Coordinator uses its own managed folder, never a repo checkout. Existing Run Conversation storage retains messages and agent output; additive Coordinator events persist identity, Run associations, phase, referenced Tasks and action receipts. Concurrent first messages share the Factory’s unique row. Replacement association includes its launch prompt and pending input in the same persisted Coordinator event, so a restart before host creation can resume that request. Stop archives undispatched messages with their removal from the dispatch queue in one store commit; they remain visible as Not sent and are never replayed by a later message.

The stored Run association supplies authority, rather than a request’s Factory ID or an environment variable. The server restricts these Runs to Coordinator tools, caller discovery and their own boundary operation. Ordinary Run routes cannot bypass that restriction. App-only routes create conversations, send human messages, Stop and Retry. The daemon shares one steering service between Conversations and Coordinator. Coordinator owns idle-turn admission; steering owns every queued message delivery through its serialized chain, including delivery after admission. A Coordinator message stays queued until the agent acknowledges it. RunManager dispatch writes and syncs a generation-tagged input record carrying the message’s stable delivery ID and the host-output offset. Retrying after a daemon restart recognizes an already written or accepted delivery instead of appending it again. These are additive fields in the existing generation envelope, which older hosts already unwrap. Steering retains admission until an in-flight dispatch completes, including settlement during persistence; Stop, removal and shutdown close its dispatch gate. Steering’s boundary flag and hook handle working responses, while its observers cannot deliver an idle Coordinator follow-up around the queue. Canceling the last queued message returns the conversation to Ready without taking a slot. Replacement Run association retains the admitted Working phase until the response settles. Failed session resumption can replace the Run while preserving earlier history and receipts. Old Runs have no action authority.

Reads return fresh facts with bounded pages and nonce-delimited untrusted Task context. Actions require current target and neighbour versions. Starts delegate to `Tasks.start`; moves delegate to `Tasks.move`, using neighbour IDs rather than client ranks. The daemon validates Factory and waiting-group membership. Per-action operation IDs and fingerprints are persisted before dispatch; an interrupted dispatch returns an uncertain receipt rather than replaying the action. Receipts preserve the actual result and before/after state, including Priority changes. Multi-Task actions are independent, never atomic.

Startup restores steering flags after Coordinator admission state is available. Health recovery drains launch and steering before checking for pending input, persists a continuation when needed, and only then stops and requeues the interrupted response. Retry reuses pending input before adding a continuation. Shutdown closes admission and drains launches, steering, action chains and health recovery before the store closes. Factory removal blocks Coordinator creation from its start through final cleanup and rechecks first-message creation after defaults resolve. It waits for launches and actions, stops Coordinator hosts and removes saved rows, pending messages, Conversation history and checked managed folders before FactoryRemoved. This is an explicit, narrow Factory-scoped exception to ordinary Task Run authority. It grants no power over Gates, arbitrary Stages, Task edits, credentials or settings.
