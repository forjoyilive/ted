# Trackers sync through one shared module

Linear sync (ADR 0090) lived in `tasks/linear-sync.ts`, `tasks/request-linear-team.ts` and three functions in `tasks/tasks.ts`. Asana sync (TED-317 to TED-319) and later GitHub issues need the same rules: per-Task and per-group permission, one Inbox question for a new group, the handling of an item closed outside Ted, and records of what was seen, moved and linked. Copying that code per tracker would let the rules drift apart.

**The shared part is `packages/daemon/src/tasks/tracker-sync/`.** `createTrackerSync` in `sync.ts` runs one cycle at a time, a full interval after the last one ends (longer when a read asks to wait), and reads nothing while the connector’s switch is off or `ready()` is false. For each watched Task (its source is the connector’s, it is open, or it merged with a step or a pull request link left) it records what it read, stops unless the Task’s sync is `on`, handles a closing, asks the connector to move the item, and links each new pull request. A step is never repeated or moved backwards, and nothing is written for a Task archived without merging. An item closed outside Ted is a baseline on the first read; later, open to closed archives the Task when no Run is live, it hasn’t reached Merge and no Task that isn’t archived is under it, even when it has a parent, and posts a Ted note on that parent naming the archived Task; otherwise it posts one Archive or Keep going question, withdrawn when the item reopens or the Task finishes. Archiving goes through callbacks into `tasks.ts`, so only the Tasks module changes Tasks. `createTrackerConsent` in `consent.ts` allows one Task, posts the new-group question with Allow and Not now, and answers it; Allow turns on the group’s waiting Tasks in that Factory.

**A tracker plugs in a `TrackerConnector`** (`connector.ts`): it recognises a Task’s source, reads many items in bounded requests (or asks the next cycle to wait, for `Retry-After`), decides and makes a move (or declines, such as a parent still waiting on items under it), links one pull request, and names its groups, the texts of its two questions and the parent’s note when a Task under it is archived. Every request and credential stays in the tracker’s own folder (`linear/`, `asana/`).

**Records are a second seam, `TrackerRecords`.** Linear’s records (`linearRecords` in `tasks/linear-sync.ts`) read and write the shipped `v1.Linear*` events, the `linear-closed` and `linear-team` purposes, the `linearTeam` Comment field and the `linearSync*` settings, so Linear behaves and stores exactly as before. Every later tracker uses `trackerRecords` (`records.ts`): the `v1.TrackerItemSeen`, `v1.TrackerItemMoved`, `v1.TrackerPullRequestsLinked`, `v1.TrackerSyncAllowed` and `v1.TrackerGroupSyncAllowed` events keyed by tracker ID, the `tracker-closed` and `tracker-group` purposes (the group lives in the purpose), the `tracker` withdrawal reason, and the `trackerSyncGroups` and `trackerSyncDeclined` machine settings (tracker, then Factory, then group IDs). The two permission events carry an optional `account`, because shipped events can’t gain a field and Asana permission is tied to the connected account. Like the `v1.Linear*` rows, these Task log rows stay through `v1.TaskReset` (`trackerSyncLog` in `store/schema.ts`) and go with the Task; Factory removal deletes the Factory’s group lists.

**In the app,** `settings/TrackerGroupsRow.tsx` draws a Factory’s allowed groups with the Not now list and its Allow buttons around the tracker’s own input, and `trackerSyncOf` in `renderer/tracker-sync.ts` gives the Task menu and Task actions their Sync with … item.

## Considered Options

- **One neutral record set for Linear too, reading the old events as a legacy source.** Rejected: two readers of the same consent are easy to get wrong, and Linear’s consent must keep reading the shipped events.
- **Leave the neutral events to the first tracker that needs them.** Rejected: the shared module owns the records, and its test with a fake connector runs on the real store.

## Consequences

Adding a tracker means a connector, `trackerRecords(store, '<id>')`, its texts and a name in `trackerName` (`packages/protocol/src/task.ts`); nothing in Linear’s connector changes. Any new tracker question kind must be left out of what holds a merge or an idle nudge, as `isTrackerClosedQuestion` and `isTrackerGroupAsk` are, and Autopilot and the Coordinator never answer a group question.
